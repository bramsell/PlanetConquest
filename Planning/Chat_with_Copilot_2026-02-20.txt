## Current Goal-to-Action Mapping System

Here's the architecture you're using - it's a **capability-based reasoning system** rather than a hardcoded matrix:

### **The Flow** (AITeamController.cpp)

```
Personality → Desires → Goals → Actions
```

**Layer 3 (Goals → Actions)** uses this process:

### **1. Asset Capabilities** ([Lines 75-113](AITeamController.cpp#L75-L113))

Each buildable asset has stats:
```cpp
Vehicle:  Speed=500, Damage=20,  Health=100, Income=$0/min
Turret:   Speed=0,   Damage=30,  Health=200, Income=$0/min  (STATIONARY)
Factory:  Speed=0,   Damage=0,   Health=300, Income=$2400/min (CAN'T ATTACK)
```

### **2. Goal Requirements** ([Lines 133-183](AITeamController.cpp#L133-L183))

Each goal declares what it needs:
```cpp
ConquerEnemy:      bNeedsReachTarget=true, bNeedsDealDamage=true
DefendTerritory:   bNeedsDealDamage=true, bNeedsTankDamage=true
EconomicGrowth:    bNeedsGenerateIncome=true (+ reach if resources exist)
MilitaryBuildup:   bNeedsDealDamage=true, bNeedsTankDamage=true
```

### **3. Axiom-Based Derivation** ([Lines 234-390](AITeamController.cpp#L234-L390))

The system **derives** how well an action satisfies a goal using **game physics axioms**:

```cpp
DeriveContribution(VehicleCapabilities, ConquerEnemy):
  ✓ Can reach target? (Speed=500 > 0) → +1.0 (scaled by travel time)
  ✓ Can deal damage? (Damage=20) → +1.0 (scaled by damage ratio)
  → TOTAL: ~2.0 contribution

DeriveContribution(FactoryCapabilities, ConquerEnemy):
  ✗ Can reach target? (Speed=0, needs movement) → AXIOM VIOLATION
  → TOTAL: 0.0 (factories can't conquer cities!)
```

**Key Axioms:**
- `CanReachTarget()`: Speed=0 AND Distance>0 = **impossible**
- `CalculateTravelTime()`: Time = Distance ÷ Speed
- Income generation scales with ratio to baseline ($2400/min)

### **4. Personality Quirks** (Line 643, header)

Small adjustments to contributions (not currently used):
```cpp
TMap<TPair<EAIAction, EStrategicGoal>, float> PersonalityQuirks;
```

This would allow: `PersonalityQuirks[{BuildTurrets, DefendTerritory}] = +0.2` for a "defensive-minded" AI.

## **Are there theories or learning mechanisms?**

### **Currently: NO**

The system is:
- ✅ **Deductive** (derives contributions from axioms)
- ✅ **Dynamic** (requirements change with game state)
- ❌ **Not learning** (no memory, no hypothesis testing)
- ❌ **Not theory-based** (no "I believe X works for Y" models)

## **Theory Integration - Design Thoughts**

Your idea about theories changing action-goal mappings is **very interesting**. Here's how it could work:

### **Concept: "Strategic Theories"**

A theory would be a hypothesis about action effectiveness:

```cpp
struct FStrategicTheory
{
    EAIAction Action;
    EStrategicGoal Goal;
    FString Hypothesis;  // e.g., "Turrets are effective for defense"
    
    float Confidence;    // 0.0-1.0 belief strength
    int32 Trials;        // How many times tested
    int32 Successes;     // How many worked
    
    float BonusContribution;  // Applied if confident enough
};
```

### **Learning Loop:**

1. **Form Theory**: After a goal succeeds/fails, observe what actions contributed
   - Goal: DefendTerritory, Used: BuildTurrets → City survived? → Record success
   
2. **Update Confidence**: Bayesian updates
   - Success → `Confidence += (1.0 - Confidence) * 0.3`
   - Failure → `Confidence *= 0.7`

3. **Apply Bonus**: High-confidence theories boost contributions
   ```cpp
   float BaseContribution = DeriveContribution(Caps, Reqs);
   float TheoryBonus = GetTheoryBonus(Action, Goal);  // 0.0-0.5 based on confidence
   return BaseContribution + TheoryBonus;
   ```

### **Alternative: Intent-Based Theories**

Since you now have **target-based intents** (Capture, Raid, Harass, Contain), theories could be about **intent effectiveness**:

```cpp
"Harass intent works well against high-threat cities"
"Raid intent fails if threat > 3.0"
"Contain intent is useless" (learns to never do it)
```

### **Why This Could Be Powerful:**

- AIs would **specialize** based on experience
- Cautious AI learns "Turrets saved me" → builds more turrets
- Aggressive AI learns "Raids always fail" → switches to direct Capture
- **Emergence**: Two identical AIs diverge based on random early outcomes

---

**Should we implement this?** I'd recommend:
1. Get target-based AI working well first
2. Add basic theory recording (observation only, no learning)
3. Then add confidence updates and bonus application

The current capability system is **very good** - it prevents nonsense like "factories should conquer cities." Theories would **refine** it, not replace it.
