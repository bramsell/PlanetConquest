## The Stamping Algorithm

```python
def stamp_heightmap(planet_map, stamp_map, position, radius, blend_falloff):
    # position = where on planet to place stamp (0-1 UV coordinates)
    # radius = how large the stamp appears on the planet
    # blend_falloff = how sharply edges blend (higher = sharper)
    
    for y in range(planet_map.height):
        for x in range(planet_map.width):
            # Distance from stamp center in UV space
            dist = distance(x/planet_map.width, y/planet_map.height, position)
            
            if dist < radius:
                # Sample stamp map at normalized position within radius
                stamp_uv = (x - position) / radius  # -1 to 1
                stamp_value = stamp_map.sample(stamp_uv)
                
                # Blend factor - smooth at edges
                blend = 1.0 - smoothstep(radius * blend_falloff, radius, dist)
                
                # Add volcano height on top of terrain
                planet_map[y][x] += stamp_value * blend
    
    return planet_map
```

The `blend_falloff` parameter is what makes the volcano base fade naturally into surrounding terrain. Set it around 0.6-0.8 for a gradual merge.

## The Preprocessor Approach You're Describing

Yes, this is doable. What you want is essentially a **pre-distorted flat map** that becomes correct when projected. This is exactly how texture artists handle UV unwrapping in reverse.

The math is straightforward — for any point on your flat patch, you can calculate where it will end up on the sphere after projection, then work backwards to pre-compensate:

```python
import numpy as np

def preprocess_patch_for_sphere(flat_vertices, planet_radius, 
                                 patch_center_lon, patch_center_lat):
    """
    Takes flat patch vertices and redistributes them so that after
    spherical projection the result is evenly spaced.
    
    flat_vertices: array of (x, y) positions in -1 to 1 range
    patch_center: where on sphere this patch will be placed (radians)
    """
    corrected = []
    
    for (fx, fy) in flat_vertices:
        # How far is this point from patch center (as fraction of patch size)
        dist_from_center = np.sqrt(fx**2 + fy**2)
        
        # Angular size this distance represents on the sphere
        # Flat distance maps to angle: angle = dist * (patch_angular_size / 2)
        patch_angular_radius = 0.4  # radians, tune based on patch size
        angle = dist_from_center * patch_angular_radius
        
        # On a sphere, equal angular steps cover less flat distance near edges
        # The correction factor is 1/cos(angle) for small patches
        # For larger patches use the full spherical formula:
        if dist_from_center > 0.001:  # avoid divide by zero at center
            # Spherical correction - pull edges inward
            corrected_dist = np.sin(angle) / np.sin(patch_angular_radius)
            scale = corrected_dist / dist_from_center
        else:
            scale = 1.0
            
        corrected.append((fx * scale, fy * scale))
    
    return corrected

def project_patch_to_sphere(corrected_vertices, heights, planet_radius,
                              patch_center_lon, patch_center_lat):
    """
    Projects the pre-corrected flat patch onto the sphere surface.
    """
    sphere_vertices = []
    patch_angular_radius = 0.4  # must match above
    
    for i, (fx, fy) in enumerate(corrected_vertices):
        # Convert flat position to angular offset
        lon_offset = fx * patch_angular_radius
        lat_offset = fy * patch_angular_radius
        
        # Final sphere position
        lon = patch_center_lon + lon_offset
        lat = patch_center_lat + lat_offset
        
        # Height above sphere surface
        r = planet_radius + heights[i]
        
        # Convert to cartesian
        x = r * np.cos(lat) * np.cos(lon)
        y = r * np.cos(lat) * np.sin(lon)
        z = r * np.sin(lat)
        
        sphere_vertices.append((x, y, z))
    
    return sphere_vertices
```

## The Vertex Density Problem

For the denser vertices at edges — this is handled by generating your flat patch on a grid that's already pre-biased toward the edges:

```python
def generate_patch_grid(resolution, edge_bias=2.0):
    """
    Generates a grid with higher vertex density toward edges.
    edge_bias > 1.0 pushes more vertices toward edges.
    """
    vertices = []
    
    for i in range(resolution):
        for j in range(resolution):
            # Normalized 0-1 position
            u = i / (resolution - 1)
            v = j / (resolution - 1)
            
            # Remap to -1 to 1
            fu = u * 2 - 1
            fv = v * 2 - 1
            
            # Apply bias - push vertices toward edges
            # smoothstep inverse creates edge clustering
            biased_u = np.sign(fu) * (abs(fu) ** (1/edge_bias))
            biased_v = np.sign(fv) * (abs(fv) ** (1/edge_bias))
            
            vertices.append((biased_u, biased_v))
    
    return vertices
```

With `edge_bias=2.0` you get roughly twice the vertex density at the edges compared to the center, which compensates for the increased distortion there.

---

## The Corner Problem Specifically

Corners are the worst case because they're far from center in both axes simultaneously. The spherical correction naturally handles this — the `corrected_dist` calculation pulls corners in more than edges, which is exactly what you need:

```
Center point:    correction factor ≈ 1.0  (no change)
Edge midpoint:   correction factor ≈ 0.92 (slight pull in)
Corner point:    correction factor ≈ 0.85 (stronger pull in)
```

The corners get pulled in more automatically because they're furthest from center. You don't need special corner handling — the spherical math does it.

```python
        normalized_dist = dist_from_center / continent_radius
        base_height = 1.0 - normalized_dist * 0.7
    
    # Domain-warped noise for organic coastlines
    warp_strength = continent.roughness
    warp_x = snoise3(point.x + 1.7, point.y + 3.2, point.z + seed,
                     octaves=4) * warp_strength
    warp_y = snoise3(point.x + 8.1, point.y + 0.4, point.z + seed + 1,
                     octaves=4) * warp_strength
    
    noise_val = snoise3(
        point.x + warp_x,
        point.y + warp_y, 
        point.z + seed + 2,
        octaves=6,
        persistence=0.5,
        lacunarity=2.0
    ) * 0.4  # noise contributes 40% of final height
    
    return base_height + noise_val
```

## The Hybrid Approach

This is actually the cleanest solution:

```
Stamp:    The base footprint of the feature
          Gentle raised mound where the arch sits
          Blends seamlessly into surrounding terrain

Asset:    The arch itself as a separate mesh
          Placed on top of the stamped mound
          Now it sits naturally because terrain rises to meet it
          No hard edge between flat planet and base of arch
```

The stamp doesn't need to represent the arch — it just needs to raise the terrain enough that the asset base doesn't clip or float. A simple gaussian bump stamp works for almost any asset:

```python
def gaussian_stamp(planet_map, position, radius, height, falloff=2.0):
    """
    Raises terrain in a smooth gaussian bump at position.
    Works as base for any surface asset regardless of topology.
    """
    for y in range(planet_map.height):
        for x in range(planet_map.width):
            dist = angular_distance_to(x, y, position)
            if dist < radius:
                # Gaussian falloff - smooth natural mound
                influence = np.exp(-falloff * (dist/radius)**2)
                planet_map[y][x] += height * influence
    
    return planet_map
```

Every surface asset gets a gaussian base stamp regardless of complexity. The asset's actual geometry handles everything above the surface.

## Lague's Cube Sphere vs Golden Ratio Spiral

For your use case — heightmap terrain with textures — the cube sphere is correct. Ignore the spiral for now.

## How Continent Seeding Works On A Cube Sphere

The cube sphere gives you a mesh. The continent seeding gives you a heightmap. They connect through a simple lookup:

```
For each vertex in cube sphere mesh:
    1. Get its position on sphere surface (normalized XYZ)
    2. Convert to longitude/latitude
    3. Sample heightmap at that UV position
    4. Push vertex outward by height value
    5. Assign biome color based on height + position
```

The continent seeding doesn't modify the mesh directly — it generates a 2D heightmap texture, and the mesh samples that texture. Clean separation between generation and geometry.

```cpp
// In Unreal, applied per vertex during planet mesh generation:
FVector SpherePoint = VertexPosition.GetSafeNormal();

// Convert to UV for heightmap sampling
float Lon = FMath::Atan2(SpherePoint.Y, SpherePoint.X);
float Lat = FMath::Asin(SpherePoint.Z);
FVector2D UV = FVector2D(
    (Lon + PI) / (2 * PI),
    (Lat + PI/2) / PI
);

float Height = HeightmapTexture->Sample(UV);
VertexPosition = SpherePoint * (PlanetRadius + Height * HeightScale);
```

## How Continents Grow — The Noise Function

Growing a continent from a seed point is a **distance field modified by noise**. Here's the intuition:

```
Start with a seed point (continent center)
Calculate distance from seed to every point on sphere
Points within radius = land, points outside = ocean
BUT — add noise to the radius threshold so the boundary is irregular
Result = organic blob shape
```

```python
def get_height_at_point(sphere_point, continent_centers, seed):
    
    # Find nearest continent and its distance
    nearest_dist = float('inf')
    nearest_continent = None
    second_dist = float('inf')  # for ridge generation between continents
    
    for continent in continent_centers:
        dist = angular_distance(sphere_point, continent.position)
        if dist < nearest_dist:
            second_dist = nearest_dist
            nearest_dist = dist
            nearest_continent = continent
        elif dist < second_dist:
            second_dist = dist
    
    # Domain warp - distort sample point for organic coastlines
    # This is the key to making continents look natural not circular
    warp_strength = nearest_continent.roughness * 0.5
    
    wx = snoise3(sphere_point.x * 2.1 + 1.7,
                 sphere_point.y * 2.1 + 3.2,
                 sphere_point.z * 2.1 + seed,
                 octaves=3) * warp_strength
                 
    wy = snoise3(sphere_point.x * 2.1 + 8.1,
                 sphere_point.y * 2.1 + 0.4,
                 sphere_point.z * 2.1 + seed + 1,
                 octaves=3) * warp_strength
                 
    wz = snoise3(sphere_point.x * 2.1 + 4.3,
                 sphere_point.y * 2.1 + 6.7,
                 sphere_point.z * 2.1 + seed + 2,
                 octaves=3) * warp_strength
    
    warped_point = normalize(sphere_point + Vector3(wx, wy, wz))
    warped_dist = angular_distance(warped_point, nearest_continent.position)
    
    # Continent radius - how far it grows from seed
    continent_radius = nearest_continent.size * 0.65  # radians
    
    # Base height from distance
    if warped_dist < continent_radius:
        # Inside continent - land
        # Normalized 0 at coast, 1 at center
        t = 1.0 - (warped_dist / continent_radius)
        base_height = smoothstep(0, 1, t) * 0.6
    else:
        # Outside - ocean, drops below sea level
        ocean_depth = (warped_dist - continent_radius) / 0.4
        base_height = -min(ocean_depth, 1.0) * 0.3
    
    # Terrain detail noise layered on top
    # This gives hills, valleys, coastal variation
    detail = snoise3(
        sphere_point.x * 4 + seed + 10,
        sphere_point.y * 4 + seed + 11,
        sphere_point.z * 4 + seed + 12,
        octaves=6,
        persistence=0.55,
        lacunarity=2.1
    ) * 0.25
    
    # Mask detail noise - only apply on land, fade at coasts
    land_mask = smoothstep(-0.05, 0.15, base_height)
    
    return base_height + detail * land_mask
```

```
Angular distance field:   Creates a circular continent
Domain warp:              Distorts circle into irregular blob
                          Higher roughness = more peninsulas and bays
Smoothstep falloff:       Continent slopes gently to coast
                          No sharp cliff at shoreline
Detail noise:             Hills and valleys within continent

```

```python
    continental = snoise3(
        sphere_point.x * 0.8 + seed,
        sphere_point.y * 0.8 + seed,
        sphere_point.z * 0.8 + seed,
        octaves=1,
        persistence=0.5
    ) * 0.4
    
    # Layer 2: Regional scale (medium frequency)  
    # Creates mountain ranges, plains, basins
    regional = snoise3(
        sphere_point.x * 2.5 + seed + 10,
        sphere_point.y * 2.5 + seed + 10,
        sphere_point.z * 2.5 + seed + 10,
        octaves=3,
        persistence=0.5,
        lacunarity=2.0
    ) * 0.25
    
    # Layer 3: Local detail (high frequency)
    # Hills, ridges, surface texture
    local = snoise3(
        sphere_point.x * 8.0 + seed + 20,
        sphere_point.y * 8.0 + seed + 20,
        sphere_point.z * 8.0 + seed + 20,
        octaves=4,
        persistence=0.45,
        lacunarity=2.2
    ) * 0.12

    # Fine surface roughness, rock texture feel
    micro = snoise3(
        sphere_point.x * 20.0 + seed + 30,
        sphere_point.y * 20.0 + seed + 30,
        sphere_point.z * 20.0 + seed + 30,
        octaves=2,
        persistence=0.4
    ) * 0.05
    
    # Base offset pushes whole planet above or below sea level
    base = planet_profile.base_height_offset  # e.g. +0.3 for land world
    
    return base + continental + regional + local + micro
```

## Combining With Continent Seeds

The seeds modify the base terrain rather than replacing it:

```python
def get_final_height(sphere_point, seeds, planet_profile, seed):
    
    # Start with layered base terrain
    base = generate_base_terrain(sphere_point, seed, planet_profile)
    
    # Find influence from nearest continent seed
    seed_influence = calculate_seed_influence(sphere_point, seeds, planet_profile)
    
    # RAISED mode: seeds push above sea level (classic continents)
    # SUNKEN mode: seeds push below sea level (lakes/seas on land world)
    if planet_profile.seed_type == SeedType.RAISED:
        return base + seed_influence
    else:  # SUNKEN
        return base - seed_influence


def calculate_seed_influence(sphere_point, seeds, planet_profile):
    
    nearest_dist = float('inf')
    nearest_seed = None
    
    for s in seeds:
        dist = angular_distance(sphere_point, s.position)
        if dist < nearest_dist:
            nearest_dist = dist
            nearest_seed = s
    
    if nearest_dist > nearest_seed.radius:
        return 0.0  # outside all seed influence
    
    # Normalized distance within seed radius
    t = nearest_dist / nearest_seed.radius
    
    # Domain warp for organic edges
    warped_dist = apply_domain_warp(sphere_point, nearest_dist, nearest_seed)
    t_warped = warped_dist / nearest_seed.radius
    
    # Smooth falloff - strong at center, fades at edge
    influence = smoothstep(1.0, 0.0, t_warped) * nearest_seed.strength
    
    return influence
```

## The Resolution / Performance Problem

The slowdown isn't from rendering — it's from **CPU-side generation**. You're calculating `CalculateHeightAtPoint` for every vertex on the CPU, which scales as resolution². At 512 per face × 6 faces = 1.5 million vertices, each requiring noise sampling and angular distance checks against every continent seed. That's slow.

Games with smooth planets solve this with one or both of:

**GPU generation** — run the height calculation as a compute shader. Same math, but runs on thousands of GPU cores simultaneously instead of one CPU core. 512² resolution that takes seconds on CPU takes milliseconds on GPU.

**Heightmap texture approach** — generate the heightmap once at high resolution as a texture (in Python or a compute shader), then the mesh just samples it. Generation happens once offline or at load time, not per-frame.

**LOD (Level of Detail)** — higher resolution near camera, lower resolution far away. You're already planning this.

For now the pragmatic fix is: **generate the heightmap in Python at high resolution, export as PNG, import to Unreal, mesh samples the texture.** Your Python script can take 10 seconds to generate — that's fine for offline generation. The Unreal mesh just reads the pre-baked texture instantly.

The zigzagging at 128 is a vertex count problem — coastlines need enough vertices to approximate smooth curves. At 128 per face you have roughly one vertex every 1500 units on a 200k planet. Coastline curves smaller than that get staircased. The texture approach solves this because the heightmap can be 2048×2048 regardless of mesh resolution — the mesh interpolates between samples smoothly.

## The Continent Overlap And Configuration Problem

You're right that only spacing seed centers doesn't prevent continent bodies from overlapping. The cracked shell idea is actually a great intuition — it's essentially **Voronoi-based continent generation**, which is exactly how many planet generators handle this.

The approach:

```
1. Place N seed points on sphere with guaranteed spacing
2. Every surface point belongs to its nearest seed (Voronoi cell)
3. Each cell becomes a continent — guaranteed no overlap by definition
4. Add noise to cell boundaries for organic coastlines
5. Control which cells are land vs ocean
```

```python
def get_voronoi_continent_height(sphere_point, seeds, sea_level_offset):
    
    # Find nearest and second nearest seed
    distances = [(angular_distance(sphere_point, s.position), s) 
                 for s in seeds]
    distances.sort(key=lambda x: x[0])
    
    nearest_dist, nearest_seed = distances[0]
    second_dist, second_seed  = distances[1]
    
    # Voronoi boundary = where nearest and second nearest are equidistant
    # Distance to boundary:
    boundary_dist = (second_dist - nearest_dist) / 2.0
    
    # Domain warp for organic coastlines
    warped_point = domain_warp(sphere_point, nearest_seed.roughness * 0.4, seed)
    warped_nearest = angular_distance(warped_point, nearest_seed.position)
    warped_second  = angular_distance(warped_point, second_seed.position)
    warped_boundary = (warped_second - warped_nearest) / 2.0
    
    # Each seed decides if it's land or ocean
    if not nearest_seed.is_land:
        return 0.0  # This cell is ocean
    
    # Land cell - height based on distance to boundary
    # Peaks at center, slopes to coast
    continent_radius = nearest_seed.size * 0.5  # fraction of cell
    
    if warped_boundary > 0:  # Inside land cell
        return 1.0  # Binary land
    else:
        return 0.0  # Ocean
```

The key property: **Voronoi cells never overlap**. Each point on the sphere belongs to exactly one seed. Continent boundaries are always equidistant between two seeds. Zero overlap guaranteed mathematically.

## Continent Configuration Control

For controlling the arrangement — equidistant, linear, two-close-one-far — rather than purely random placement, use **explicit configuration templates**:

```python
class ContinentConfiguration(Enum):
    EQUIDISTANT_TRIANGLE  = "triangle"   # 3 continents evenly spaced
    LINEAR                = "linear"     # 3 continents in a line
    TWO_CLOSE_ONE_FAR     = "asymmetric" # 2 near each other, 1 opposite
    POLAR_BAND            = "band"       # continents in equatorial band
    RANDOM                = "random"     # current behavior

def place_main_continents(config, num_continents, rng):
    
    if config == ContinentConfiguration.EQUIDISTANT_TRIANGLE:
        # 3 points evenly distributed on equator, 120 degrees apart
        centers = []
        for i in range(num_continents):
            angle = (2 * PI / num_continents) * i
            lat = rng.uniform(-0.3, 0.3)  # slight latitude variation
            lon = angle + rng.uniform(-0.15, 0.15)  # slight longitude variation
            centers.append(spherical_to_cartesian(lon, lat))
        return centers
    
    elif config == ContinentConfiguration.LINEAR:
        # Continents arranged in an arc across one hemisphere
        centers = []
        for i in range(num_continents):
            t = i / (num_continents - 1)  # 0 to 1
            lon = lerp(-PI * 0.5, PI * 0.5, t)
            lat = rng.uniform(-0.2, 0.2)
            centers.append(spherical_to_cartesian(lon, lat))
        return centers
    
    elif config == ContinentConfiguration.TWO_CLOSE_ONE_FAR:
        # Two continents near each other, one on opposite side
        c1 = spherical_to_cartesian(0, rng.uniform(-0.3, 0.3))
        c2 = spherical_to_cartesian(
            rng.uniform(0.4, 0.7),   # close to c1
            rng.uniform(-0.3, 0.3)
        )
        c3 = spherical_to_cartesian(
            PI + rng.uniform(-0.3, 0.3),  # opposite side
            rng.uniform(-0.3, 0.3)
        )
        return [c1, c2, c3]
    
    else:  # RANDOM
        return place_with_min_spacing(num_continents, MinSpacing, rng)
```

The slight random variation within each template means no two equidistant planets look identical, but the general configuration is always recognizable.
